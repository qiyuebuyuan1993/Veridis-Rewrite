# API 管理器双向接入

在词汇映射的 **AI → API 连接 → API 管理器 · 导入 / 保存** 中操作。

- **读取管理器分组**：列出标签分组和配置组，选择连接后点 **填入词汇映射**，复制 URL、Key、模型。当前连接自动保存；要更新命名 API 预设，使用原有预设保存按钮。
- **保存到 API 管理器**：选择当前连接或某个已保存 API 预设，填写目标分组。留空使用“词汇映射”；不存在时新建，存在时复用。保存的条目同时以目标名称作为配置组和标签分组，预设名作为条目别名。
- 同一分组已存在完全相同 URL、Key、模型时跳过，不覆盖原条目。不同 Key 或模型保留为不同条目。遇到重复的标签分组名称会提示先区分名称。

适配 [kaelisvespera/ST-Api-Scripts](https://github.com/kaelisvespera/ST-Api-Scripts) 的 2.2.8 / catalog v2 格式，核对源码提交 `82ea902c54d8ac91dbf27cbf0668a0cf7f6407b5`。普通 SillyTavern 读取扩展设置，TauriTavern 读取扩展存储 `st-api-manager/state`。需要先启用管理器；刚启用的空目录也可接收第一条配置。旧版格式会提示更新，不自动迁移或覆盖。

管理器目前没有公开写入 API，且内部缓存目录，因此不直接修改其存储。写回会短暂打开管理器原生窗口，通过“合并导入”保存，成功后关闭本次打开的窗口。已有管理器窗口未关闭时会提示先关闭。保存失败会保留管理器错误提示，绝不回退到“替换导入”。未来管理器改变导入界面时可能需要更新适配。

只保存到管理器本机目录；账户同步仍由用户在管理器内操作。Key 仅进入目标连接和管理器的原有存储，不写日志、选项标签或中间下载文件。不会切换酒馆主连接或发送模型请求。

词汇映射仍使用 OpenAI 兼容协议。支持管理器 custom、openai、deepseek 来源；后两者无 URL 时使用对应默认地址。原生 Gemini 等其他协议会提示不兼容，不伪造可用连接。

验证：纯函数测试；使用对方未修改 bundle 的桌面/手机宽度隔离浏览器测试，覆盖 ST 扩展设置、模拟 TT 存储、原生合并、重复跳过、刷新持久化、旧条目/备注保留和存储失败。不是 Android TT 真机或真实模型验证。

运行 `node --test tests/api-manager.mjs`；浏览器测试 `node tests/api-manager-ui.mjs` 需要 `API_MANAGER_BUNDLE` 指向上述版本管理器 `index.js`，可用 `BLAI_TEST_MODULES` 和 `BLAI_TEST_CHROME` 指定 Playwright 与浏览器。对方源码不包含在词汇映射发布包中。
